Current phase: converging the playable macOS ARM64 core bundle with the proven Aurora Metal and native mobile touch/platform paths.

- Pinned Aurora commit `5027ed63…` now builds and runs its GX example natively on macOS ARM64 through Dawn's Metal backend. Runtime logs identify the Apple M2 Metal adapter and the visible example framebuffer renders correctly.
- A compiled-object coverage audit inspects 3,905 game-core objects and finds 112 required GX/GD symbols. Bellpad's pinned Aurora patch implements the five former gaps (`GXAbortFrame`, `GXReadXfRasMetric`, `GXSetCopyClamp`, `GXSetCurrentGXThread`, and `GXSetScissorBoxOffset`); patched `libaurora_gx.a` provides all 112 with zero missing.
- A compiled ABI probe proves all GX value types match size/alignment. The core's opaque texture storage exceeds Aurora's requirement, and patch 13 expands PC-only `GXTlutObj` storage from 16 to 40 bytes to prevent an Aurora palette-object overwrite. The full 3,361-step incremental macOS app rebuild and link passed afterward.
- A dedicated Aurora core target compiles all 3,904 game objects with the production renderer path enabled. Its 111 GX/GD imports have zero gaps, it imports none of the 11 former OpenGL-only frame/batch/diagnostic hooks, and an explicit Aurora host-endian TLUT API preserves palettes generated by `emu64`. The temporary playable OpenGL app also relinks after the split.
- A native ARM64 `BellpadAurora` target now links that complete game core to pinned Aurora, Dawn/Metal, and SDL3 without loading SDL2. Its clean 4,258-action build passes and the resulting Mach-O selects the Apple M2 Metal adapter.
- A real runtime smoke validates the private GAFE01 image, indexes its files, loads 14,495 assets, mounts all game archives, opens a 32 kHz stereo SDL3/CoreAudio stream, enters `graph_proc`, advances the title actor through its setup states, and remains interactive at the title menu at 60.0 FPS.
- The title image through Aurora is recognizable, including menu text and choices, but geometry and portions of the scene remain visibly corrupted. Static host-endian palette decoding now produces plausible title/tree colors, and disabling Aurora's unsafe cross-draw merge removes the worst full-screen polygon spikes. This is command-flow and integration evidence only; correct rendering is not claimed.
- The first corruption class was lifecycle-related rather than a texture decoder: bypassing JSystem's blocking `beginRender` also skipped its EFB clear, so moving title frames accumulated. The Aurora boundary now clears color/depth through JSystem, restores the 2D port, invalidates caches, and performs display-manager end-render work. A repeated smoke shows a stable black background and one current frame instead of the gray smear.
- A second renderer audit found three source-level compatibility defects. Aurora normalized host-endian TLUTs for dynamic textures but not static paletted textures, treated the game's per-frame `GXInvalidateTexAll` as a no-op, and merged emu64 draws whose reused texture/matrix dependencies were not represented by the merge key. Aurora patch 3 fixes the static palette path, connects invalidation to its cache-clear mechanism, and conservatively isolates draws. A pre-fix long title run eventually reported Metal texture-allocation failure; post-fix smoke reached 5,000 frames without that failure, but a measured multi-hour memory soak is still required.
- Runtime debugging resolved two convergence blockers. JSystem was waiting forever on a GameCube VI message queue after Aurora acquired its first frame, so the native target now uses synchronous Aurora frame boundaries and the established desktop retrace pacing. The first input update then tripped stack protection because Aurora's extended 16-byte `PADStatus` was being written into a 12-byte-stride game array; the Aurora build now matches that ABI explicitly.
- The same pinned Aurora GX example now compiles as an ARM64 `IOSSIMULATOR` executable with vendored SDL3 and source-built Dawn. It installs and visibly renders through the Apple iOS simulator Metal GPU on an iPhone 17 Pro simulator and, only after stopping that session, an iPad Pro 13-inch simulator.
- The iOS probe establishes compatibility-layer feasibility, not a Bellpad product target. Upstream's packaged Dawn iOS archive is device-only; simulator builds require source Dawn plus Ninja at this revision. The upstream generic example also needs product-owned bundle metadata and adaptive window/layout policy.
- Bellpad now owns native ARM64 macOS and universal iOS/iPadOS application targets with explicit bundle metadata. Both use MetalKit at a requested 60 FPS, keeping high-refresh displays from accelerating the future VI-coupled simulation.
- The mobile target installs and launches sequentially on iPhone 17 Pro and iPad Pro 13-inch simulators. Its first-pass GameCube touch UI includes left/C sticks, A/B/X/Y, Z/L/R/Start, and D-pad; it scales from compact resizable iPad windows to a distinct expanded iPad layout and respects safe-area insets.
- A thread-safe portable input mixer now merges touch and GameController sources with ORed buttons, strongest-magnitude axes, and maximum analog triggers. A native unit test proves those merge and clear rules. Device builds auto-hide touch for physical controllers; simulator-generated controllers remain visible for touch-layout QA.
- The macOS shell launches as a normal resizable app, visibly renders its Metal view, accepts GameController state through the same mixer, and quits through the normal application path.
- Bellpad now presents native `NSOpenPanel` and `UIDocumentPickerViewController` interfaces. Both feed a shared data-only validator that accepts `.iso`/`.gcm` only when the 32-byte header contains GameCube magic, `GAFE01`, and revision 0. It never hashes, copies, bookmarks, or retains the selected file yet.

## Active blockers

- Apple Clang compilation no longer blocks iOS work, but the address model still needs sanitizer coverage and a complete audit of guest offsets versus native pointers.
- The new town did not reach its first successful GCI write before the reproducible house-transition crash; the crash is patched, but a fresh run through save, controlled exit, and reload is required, so persistence remains unproven.
- Computer Use key synthesis is not consistently delivered to SDL in the current app-wrapper harness. The Homebrew dependency is `sdl2-compat` over SDL3, so raw SDL2 event-memory injection is not a valid substitute. `scripts/tap-desktop-button.sh` instead feeds the port's normalized pad queue under LLDB for deterministic desktop QA; save/relaunch automation still needs text and analog injection.
- The text editor now has SDL-independent begin/end, UTF-8 commit, and command functions suitable for a UIKit adapter. The guarded desktop helper entered `Bell`, closed that editor, reopened the destination editor, and entered `Cedar`; both values were rendered by Rover.
- A normalized virtual-pad state now covers GameCube buttons, both sticks, and analog triggers. Runtime `PADRead` evidence matched every requested byte and derived L/R trigger bit. Persistent and frame-counted helpers have driven outdoor movement, inventory, planting, and resident dialogue; the first save/relaunch proof remains pending.
- The two new scene fixes are compiler-verified on both ARM64 toolchains and the rebuilt title smoke test passes, but neither is marked runtime-passed until a fresh town reaches an NPC-house interior and returns outdoors.
- The current fresh run reached a villager house after the planting tutorial, but its resident was visibly outdoors, so the closed door did not exercise scene allocation. The process staying alive at that door is not counted as patch-7/8 proof.
- A later occupied-house route was derived from the runtime town combination table and collision grids. The targeted villager left home before Bell arrived, and a second occupied target likewise changed to outdoors during the route. Runtime `is_home` flags and the visible villagers agreed, so patch-7/8 runtime status remains pending without manufacturing a false pass.
- SDL window close/Command-Q and full cleanup still require a clean retest. The earlier instrumented app-wrapper run needed `SIGKILL`, while the fresh scripted executable terminates on `SIGTERM`; the conflicting evidence is kept explicit.
- Animal Crossing now renders through Aurora GX/Metal and per-frame clearing/static palette byte order are correct, but the emu64-rendered composition still has missing or incorrectly placed geometry while host-native menu text is stable. Matrix/projection, vertex interpretation, and retained GX state are the immediate convergence audit.
- The native Metal/touch shells still do not link the game core or Aurora services. `BellpadAurora` proves the real core and compatibility layer can coexist, but it remains a transitional macOS executable: product input, Files retention, Application Support, native lifecycle, and UIKit ownership are not connected.
- Aurora frame/event ownership currently crosses both JSystem and the retained desktop VI support. It is stable enough for the title smoke but must be reduced to one update point before lifecycle and mobile integration.
- The iPad expanded full-window layout is code-complete but the simulator launched this unsigned build in a 960×640 resizable window; the responsive compact fallback is visually proven there. Full-screen/expanded layout still needs a separate simulator or device run.
- Mobile disc retention, hash allowlisting, nod indexing, compressed CISO/RVZ support, Application Support storage, and actual mobile game launch remain after the shell's header-validation boundary.
- Simulator shell evidence exists, but simulator and physical-device Animal Crossing gameplay evidence do not.
