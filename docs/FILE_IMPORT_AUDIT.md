# iOS file-import audit — 2026-10-30

This is a source and issue audit of the **39 existing PadMint catalog entries**, all owned by `chrissotraidis`. It is not a device compatibility certification and does not add games to PadMint. Source links below pin the default-branch commits inspected on this date; local working copies were not treated as current because several are older or have unrelated changes.

## What the count means

- **5 projects have matching historical or current selection reports:** BellPad, KartPad, HaloPad (`projectreach`), SquirrelPad and SunPad.
- **4 have an open relevant issue:** BellPad #26, KartPad #380, HaloPad #29 and SquirrelPad #3. Their installed versions and failure stages differ. This is not proof that four current releases fail on every device.
- **5 additional projects merit priority code review:** BallPad, F0X, GalaxyPad, RA Touch and UTP. These are source findings, not confirmed affected players or builds.
- **20 other entries have a native selection path inspected without a matching report found.** Two of these inspections are partial (DaggerPad caller filters and GoldenPad build-path selection). They are not declared unaffected.
- **9 entries use another setup route in the reviewed source**, such as Files-folder discovery, builder-prepared data or a download. They are outside the specific first-run system-picker defect, but their own setup still needs normal testing.

The categories are disjoint: 5 + 5 + 20 + 9 = 39. There is no telemetry establishing how many installed builds or players are affected. An occurrence of `UTTypeData` or `asCopy:NO` alone is not a bug: compatibility depends on the selected content, provider, access mode, importer and available fallback.

## Why these reports recur

1. **Picker filtering precedes validation.** Providers can assign different types to the same extension. A supported image can be disabled before application code sees it. Prefer a broad single-file selection policy, followed by existing extension/header/revision/content validation. Broader selection must never broaden accepted game content.
2. **Single files and directories need different ownership rules.** Copy mode has fixed provider access failures for single images. A directory chooser should use a folder-only open path, then explicitly copy validated contents into app-owned staging. Do not fix every picker by setting the same Boolean; imports must never delete an external source.
3. **A fallback must exist before import succeeds.** Enable the correct Files metadata, create the Documents directory during setup, provide clear copy-in instructions, and scan the current installation's folder. A signer/container can change which Documents folder belongs to an installation.
4. **A responsive picker is only one stage.** Provider downloads, validation and copying need progress and actionable errors without blocking the main thread. SquirrelPad demonstrates how a frozen launcher can look like a selection problem.
5. **Main is not a released fix.** PadMint's normal release selection must deliver the corrected tag. SquirrelPad #8 was merged but unreleased at initial inspection; publishing 0.1.3 closed that delivery gap.

Apple documents the [copy/open distinction](https://developer.apple.com/documentation/uikit/uidocumentpickerviewcontroller/init%28foropeningcontenttypes%3Aascopy%3A%29) and [folder access API](https://developer.apple.com/documentation/uikit/providing-access-to-directories). The recommendations above also draw on the concrete project reports; they are not a claim that every provider behaves identically.

## Regression and release checks

Keep the implementation in each game's importer; PadMint owns delivery and verification, not a second game-specific importer. Maintain a small reusable acceptance checklist across projects:

- Single supported file from On My iPhone/iPad, iCloud after download, and a third-party provider where available; invalid selection gives an error without losing existing data.
- Folder import uses a separate folder-only open action; cancellation and empty/invalid folders return usable controls.
- First launch exposes the intended Files folder before any successful import; the copy-in path works without the picker.
- Import/cancel/retry does not delete originals, leave large picker copies indefinitely, replace saves, or freeze the UI.
- A PadMint build from a clean checkout and published tag produces the expected version and metadata. Recipe-only releases remain recipe-only.
- Record simulator, build and actual-device results separately. Keep issues open when exact-device acceptance is still unknown.

This audit did not build, install or exercise all 39 projects. It inspected current maintained source/patches and related GitHub issues. Existing setup paths in patches may still be affected by later upstream application, signing or container behavior; those need package and device checks. Search did not establish absence of all unreported failures.
